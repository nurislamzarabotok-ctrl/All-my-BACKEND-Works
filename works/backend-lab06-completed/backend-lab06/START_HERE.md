# Запуск и сдача

## 1. Подготовить файлы

Распаковать архив в отдельную папку. Исходный архив можно оставить как резервную копию.
Заполнить группу в `REPORT.md`.

Исправлены `schemas.py`, `errors.py`, `storage.py`, `main.py`. Заполнен `REPORT.md`.
`README.md`, `models.py`, `requirements.txt` и коллекция `bruno/` сохранены без изменений.
`test_api.py` содержит дополнительные тесты, `checks/` — результаты проверок.

## 2. Запустить на Windows

Открыть терминал в папке с `main.py`:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\fastapi.exe dev main.py
```

Документация: http://127.0.0.1:8000/docs.
Приложение хранит данные только в памяти: после перезапуска список пустой.

## 3. Проверить

В Bruno открыть папку `bruno`, выбрать окружение `local` и запустить коллекцию.
Перед каждым полным запуском коллекции перезапустить сервер, чтобы очистить сообщения.
Ожидаемый результат: 13 успешных запросов и 24 успешные проверки.

Дополнительные тесты запускаются отдельно:

```powershell
.venv\Scripts\python.exe -m unittest -v
```

Если для тестов не хватает `httpx`:

```powershell
.venv\Scripts\python.exe -m pip install httpx
```

## 4. Отправить в свой репозиторий

Если на компьютере уже есть клонированный репозиторий, скопировать в него исправленные файлы. Не удалять и не заменять его папку `.git`. Не загружать `.venv` и `__pycache__`.

Если клона еще нет, скопировать HTTPS-ссылку из зеленой кнопки Code на GitHub и выполнить `git clone` с этой ссылкой. Затем перенести исправленные файлы в полученную папку.

Перед отправкой проверить изменения:

```bash
git diff
git status
git log --oneline
```

В задании требуется минимум 7 коммитов по ходу работы. В скачанном ZIP истории Git нет. Архив содержит готовые файлы, но не подтверждает этот пункт и не создает коммиты в GitHub. Один итоговый коммит не заменяет требуемые преподавателем 7 коммитов. Если поэтапные изменения не сохранялись, этот момент нужно согласовать с преподавателем.

## Кратко по решению

- `next_id += 1`: ID не зависят от количества оставшихся сообщений.
- `field_validator`: удаление пробелов, запрет пустого текста и явного `null`.
- `extra="forbid"`: неизвестные поля PATCH дают 422.
- `MessageNotFound`: отсутствие сообщения дает 404.
- `ChatFull`: при трех сохраненных сообщениях новое дает 409.
- `exclude_unset=True`: PATCH не изменяет пропущенные поля.
