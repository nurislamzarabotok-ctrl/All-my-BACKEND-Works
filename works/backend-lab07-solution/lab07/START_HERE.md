# Lab 07: запуск и сдача

## Что в архиве

- `app/` — исправленное приложение.
- `tests/` — тесты; изменены только предусмотренные заданием файлы.
- `bruno/` — исходная коллекция без изменений.
- `REPORT.md` — ответы и реальные результаты проверок.
- `checks/` — вывод pytest, Bruno, намеренных поломок и сведения об окружении. Промежуточные красные проверки ожидаемы: финальные результаты находятся в `final-pytest.txt` и `final-bruno.txt`.
- `history/lab07.bundle` — переносимая локальная история Git.
- `history/patches/` — патчи коммитов по этапам, без исходного импорта ZIP.
- `history/git-log.txt` — список коммитов и тегов.

Исходный архив не изменен. В нем не было `.git`: оригинальная история репозитория `Danil-ai-sys` не восстановлена. Сохраненные здесь коммиты — реальная история выполненных при подготовке этапов, с автором `Notion AI`. Они не выдаются за ваши прежние коммиты и пока не отправлены в GitHub.

## Вариант A: обычная папка в общем NurikGit

Сначала сохранить копию существующей папки с тем же названием, если она есть. Затем перенести распакованную `lab07` в:

```text
C:\Users\nuris\OneDrive\Desktop\All Packs\NurikGit\works\lab07
```

Не переносить `.venv`, `__pycache__` и `.git` других проектов. В распакованном архиве `.git` отсутствует.

Из корня `NurikGit`:

```powershell
git status
git add -- works/lab07
git diff --cached --stat
```

Проверить полный список подготовленных файлов. Если там только нужные файлы и нет секретов/окружений:

```powershell
git commit -m "lab 07: solutions and checks"
git push
```

Это отправляет файлы одним текущим коммитом. **Копирование папки не переносит историю этапов в общий Git log.** Bundle и патчи при этом сохраняются как файлы. Для требования отдельных коммитов в репозитории сдачи используйте вариант B.

## Вариант B: перенести поэтапные коммиты в свой репозиторий задания

Это способ сохранить существующую историю преподавателя без force-push. Нужен именно ваш выданный репозиторий, не чужой `Danil-ai-sys`. Нельзя определить правильный адрес по имени присланного ZIP.

1. Склонировать свой репозиторий задания в отдельную папку **вне `NurikGit`**, чтобы не создавать вложенный Git-репозиторий. Если уже есть чистый клон, можно использовать его.
2. Перед применением патчей получить `git status`: рабочая папка и индекс должны быть чистыми. Если там есть ваши изменения, сначала сохранить их отдельно. Не применять патчи поверх незавершенной работы.
3. Из PowerShell в распакованной папке `lab07` выполнить команды ниже, заменив путь `$target` на путь к своему клону. Этот путь должен указывать на корень отдельного Git-репозитория, а не папку внутри общего `NurikGit`.

```powershell
$target = "C:\Users\nuris\OneDrive\Desktop\All Packs\lab07-submit"
git -C $target status
git -C $target remote -v
```

Проверить, что это нужный репозиторий и нет локальных изменений. Указать свои данные коммитера, если Git еще не настроен:

```powershell
git -C $target config user.name "ВАШЕ ИМЯ"
git -C $target config user.email "ВАШ EMAIL В GITHUB"
```

Сначала создать резервную ветку. Если такое имя уже существует, выбрать новое:

```powershell
git -C $target branch before-lab07-patches
$patches = @(Get-ChildItem ".\history\patches\*.patch" | Sort-Object Name | Select-Object -ExpandProperty FullName)
git -C $target am $patches
```

Команда применяет реальные коммиты этапов, сохраняя их авторство. Патчи проверены на исходниках из этого архива. Если ваш клон отличается, возможен конфликт. При любой ошибке **не продолжать к push**: выполнить `git -C $target am --abort`, если Git сообщает о незавершенном применении, и разобрать сообщение. Ранее успешно примененные коммиты могут остаться; резервная ветка сохраняет исходную точку. Не использовать `reset --hard` и `push --force`.

После успешного применения:

```powershell
git -C $target log --oneline -8
git -C $target status
```

Проверить проект, заполнить группу в `REPORT.md` и сохранить это отдельным коммитом. Для Lab 07 сначала также закончить Exit task. Затем проверить адрес `origin` и выполнить обычный `git push` в своем клоне.

Тег создается после окончательной проверки в том репозитории, куда требуется сдача:

```powershell
git -C $target tag -a lab07 -m "lab 07"
git -C $target push origin lab07
```

Если тег уже есть, не удалять и не перезаписывать его без проверки. Локальный тег из bundle не опубликован автоматически. Патчи не переносят теги.

## Посмотреть подготовленную историю отдельно

Из распакованной папки `lab07` можно склонировать bundle в новую папку вне `NurikGit`:

```powershell
git clone --branch main .\history\lab07.bundle "C:\Users\nuris\OneDrive\Desktop\All Packs\lab07-with-history"
```

Bundle самодостаточен и содержит `main` и локальный тег. Это копия подготовленной истории, не клон GitHub. Ее `origin` указывает на bundle, поэтому простое `git push` из такой копии не является отправкой в GitHub. Не заменять им историю существующего Classroom-репозитория: для нее предназначены патчи.
