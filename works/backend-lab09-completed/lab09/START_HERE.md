## Проверить на Windows

Открыть PowerShell в папке `lab09`:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe check.py all
.venv\Scripts\python.exe -m pytest tasks/test_b2.py tasks/test_c2.py -q
```

Активация окружения не нужна: команды вызывают Python из `.venv` напрямую. Для Lab 09 сервер отдельно не нужен. Для Lab 10 FastAPI и сервер вообще не используются.

Версии окружения, на котором выполнены проверки, записаны в `checks/environment.txt`. Подробный вывод находится в `checks/`.

## Отправить в общий репозиторий

Это действия в уже связанном `NurikGit`, а не внутри отдельной папки лабораторной. Сначала перейти в корень:

```powershell
Set-Location "C:\Users\nuris\OneDrive\Desktop\All Packs\NurikGit"
git status
git add -- works/lab09
git diff --cached --stat
```

Проверить, что подготовлены только нужные файлы, без окружений, паролей и чужих изменений. Если список верный:

```powershell
git commit -m "lab 09: solutions and checks"
git push
```

Если в индексе уже были другие файлы, `git commit` включит и их: до коммита нужно проверить полный `git status`. В случае ошибки `push` не выполнять `--force`; сначала посмотреть текст ошибки.

Эти команды создают один текущий коммит, а не историю прошлой работы. Коммиты и теги в GitHub при подготовке архива не создавались.

## Если сдача через GitHub Classroom

В README указан отдельный репозиторий задания у преподавателя. Общий репозиторий `All-my-BACKEND-Works` может не заменять сдачу туда. Если преподаватель требует Classroom, изменения нужно перенести также в клон именно выданного репозитория.

Тег `lab09` добавляется в том репозитории, куда требуется сдать работу, после проверки содержимого коммита:

```powershell
git tag lab09
git push origin lab09
```

Если тег уже существует, не удалять и не перезаписывать его без проверки. Не отправлять все теги командой `--tags`, если неизвестно, какие еще теги есть в репозитории.
